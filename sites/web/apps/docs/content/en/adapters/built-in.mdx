The platform release includes a local default adapter pack. Filesystem storage,
SQLite data stores, Pino logging, and log buffering are installed with the
platform; the runtime also supplies honest in-process defaults for event bus,
invoke, config, artifacts, analytics buffering, and notifications. Packages
listed below can be selected as overrides. Pick by interface (the contract the
runtime sees) and runtime characteristics (what backend, what tradeoffs).

To swap an adapter, change one line in `kb.config.jsonc` under `platform.adapters`. See [Adapters → Overview](/adapters) for the swap mechanics, and [Guides → LLM Setup](/guides/llm-setup) for an end-to-end walkthrough.

## LLM (`ILLM`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-kblabs-gateway` | `ILLM` | Hosted proxy, configured explicitly when you choose this provider. |
| `@kb-labs/adapters-openai` | `ILLM` | You have your own OpenAI-compatible key. Supports `baseURL` so it also works against self-hosted inference servers (vLLM, Ollama with OpenAI-compat shim, custom proxies). |
| `@kb-labs/adapters-vibeproxy` | `ILLM` | Internal routing proxy. Niche; most teams won't reach for this. |

## Embeddings (`IEmbeddings`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-openai/embeddings` | `IEmbeddings` | OpenAI text-embedding models (`text-embedding-3-small`, `-large`, etc.). Requires an explicit provider configuration. |

## Vector store (`IVectorStore`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-qdrant` | `IVectorStore` | Persistent vector database. Use for production RAG, shared indices, large corpora. |

## Cache (`ICache`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-state-broker` | `ICache` | Built-in platform-local cache backed by the StateBroker included with the platform; no Redis service is required. |
| `@kb-labs/adapters-redis` | `ICache` | Shared cache across worker processes / hosts. Standard production choice. |
| `@kb-labs/adapters-eventbus-cache` | `ICache` | Cache that publishes invalidations on the platform event bus. Use when multiple plugins share cached state and need notification of changes. |

## Storage (`IStorage`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-fs` | `IStorage` | Built-in platform default. Stores project workflow records and artifacts under `.kb/data/`; no external service is required. |

## Logger (`ILogger`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-pino` | `ILogger` | Default. Structured JSON logs to stdout. Standard production choice when something else (Loki, CloudWatch, journald) tails stdout. |
| `@kb-labs/adapters-log-ringbuffer` | `ILogRingBuffer` | In-memory log buffer for live log streaming. |
| `@kb-labs/adapters-log-document` | `ILogPersistence` | Persistent log storage backed by the configured document database. |

The default log reader combines the local logger ring buffer with SQLite log
persistence when that persistence adapter is installed. `kb adapter list
--json` reports it as `HybridLogReader`.

## Analytics (`IAnalytics`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-analytics-file` | `IAnalytics` | JSONL file at `.kb/analytics/events.jsonl`. Zero deps, append-only, easy to grep. |
| `@kb-labs/adapters-analytics-sqlite` | `IAnalytics` | Built-in platform default. SQLite database; query events with SQL and build aggregations. |
| `@kb-labs/adapters-analytics-duckdb` | `IAnalytics` | DuckDB embedded analytical database. Same single-file convenience as SQLite, much faster for analytical queries over millions of events. |

## SQL database (`ISQLDatabase`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-sqlite` | `ISQLDatabase` | Embedded SQLite. Single-file, zero-config, suitable for plugin-local persistence. |

## Document database (`IDocumentDatabase`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-sqlite` | `IDocumentDatabase` | Built-in local document database default. Embedded SQLite database at `.kb/database/kb.sqlite`. |
| `@kb-labs/adapters-mongodb` | `IDocumentDatabase` | MongoDB-backed document store. |

## Workspace (`IWorkspaceProvider`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-workspace-localfs` | `IWorkspaceProvider` | Direct read/write against the local filesystem. Default for single-machine dev. |
| `@kb-labs/adapters-workspace-worktree` | `IWorkspaceProvider` | Each plugin invocation gets its own git worktree. Isolation between concurrent runs without copying files. |
| `@kb-labs/adapters-workspace-agent` | `IWorkspaceProvider` | Routes filesystem ops through the host agent over WebSocket. Use for cloud-side workflows that need to touch a developer's local files. |

## Environment (`IEnvironmentProvider`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-environment-docker` | `IEnvironmentProvider` | Provisions a Docker container per plugin invocation when the manifest declares `execution.mode: 'container'`. |

## Snapshot (`ISnapshotProvider`)

| Package | Implements | Use when |
|---|---|---|
| `@kb-labs/adapters-snapshot-localfs` | `ISnapshotProvider` | Local filesystem snapshots used by workflow rollback and recovery. |

This provider implements the workspace snapshot-provider contract. It does not
fill the plugin-visible `snapshotManager` slot, which currently has no runtime
adapter implementation.

## Execution transport

Local execution uses `LocalBackend` and does not require a transport adapter. Remote execution receives the `IExecutionTransport` contract through `core/plugin-execution-factory`; the gateway builds `GatewayDispatchTransport`. There is no `executionTransport` key in platform configuration.

## Retry classification

Built-in adapters use the retry taxonomy exposed through the SDK facade. Custom adapters should classify failures through the SDK rather than importing the retry implementation directly:

```ts
import { classifyFailure } from '@kb-labs/sdk/adapters';

const failure = classifyFailure(error, {
  source: 'transport',
  phase: 'dispatch',
});

if (failure.transient && failure.retrySafety === 'safe') {
  // Retry only when repeating the operation is safe.
}
```

Infrastructure adapters can import the same facade from `@kb-labs/sdk/adapters/infra`. A diagnostic written to `stderr` is not, by itself, a failed adapter operation.

## What's not here yet

The roadmap-but-not-shipped list (don't try to use these via `kb.config.jsonc` — they 404):

- **Cache:** Memcached and standalone cache services beyond the platform-local StateBroker.
- **Vector store:** Pinecone, Chroma, pgvector.
- **Storage:** S3, MinIO, GCS, Azure Blob.
- **LLM:** Anthropic native, Cohere, local Llama.cpp adapter.
- **SQL:** Postgres, MySQL.

If you need one before it ships, write a custom adapter — see [Guides → First Adapter](/guides/first-adapter). Most of these are an afternoon of work because the interface is small and there's no platform plumbing to figure out.
