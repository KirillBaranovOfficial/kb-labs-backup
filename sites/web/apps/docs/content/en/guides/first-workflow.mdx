This guide creates a workflow that runs locally, prints a marker, and needs no network access or external credentials. Workflow definitions live under `.kb/workflows/` in a registered project.

Reference material lives at [Workflows → Overview](/workflows), [Workflows → Spec Reference](/workflows/spec-reference), and [Workflows → Patterns](/workflows/patterns).

## Prerequisites

- KB Labs is installed and the host is running. `kb status` should report a healthy host.
- Your project is registered. From its directory, run `kb project add` if it is not registered yet. Registration does not create files in the project.

The workflow CLI resolves the current project from its directory and sends API requests through the host's project route. Local mode uses the loopback gateway without login; secured mode requires an authenticated gateway session.

## Create and validate the example

From the project directory:

```bash
kb workflow create
kb workflow lint
```

`kb workflow create` creates `.kb/workflows/hello.yml` and will stop with an error if that file already exists. The example contains one manual workflow and one local shell step:

```yaml
name: hello
version: 1.0.0
description: A local workflow example
on:
  manual: true
jobs:
  hello:
    runsOn: local
    steps:
      - name: Print marker
        id: hello
        uses: builtin:shell
        with:
          command: echo hello-workflow
```

Lint reports that the file is valid before you start a run.

## Run and inspect it

Start the workflow:

```bash
kb workflow run --workflow-id=hello
```

Copy the run ID from the output. View its status and step output:

```bash
kb workflow runs view <run-id>
```

Replace `<run-id>` with the ID printed by the run command. The run should finish with status `success`, and the `hello` step output should contain `hello-workflow`.

## What's next

- Add a second job and connect it with `needs` to learn job dependencies.
- Add an input and pass JSON to `kb workflow run --input=...`.
- Add a scheduled trigger after reviewing [Workflow triggers](/workflows/triggers). Scheduled workflows keep their project runtime warm while enabled.

For the full field reference, see [Workflows → Spec Reference](/workflows/spec-reference). For step execution and outputs, see [Workflows → Steps](/workflows/steps).
