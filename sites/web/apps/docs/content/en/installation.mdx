The supported human installation uses the `kb-create` launcher. It installs
the platform into `~/kb-platform`, starts it, verifies its health, and adds the
`kb` command to your user environment.

## Prerequisites

- macOS or Linux.
- Node.js <NodePolicy />.x. Install it before continuing; pnpm is managed by the installer.
- At least 1.20 GiB of available memory and 2 GiB of free disk space.
- `curl` and a network connection to the KB Labs release index and package registry.

## Install

```bash
curl -fsSL https://kblabs.ru/install.sh | sh
kb-create install
```

The shell script installs the launcher in `~/.local/bin`. Ensure that directory
is on `PATH`, then run `kb-create install`. Follow the prompts to choose local
or secured access. Local access is loopback-only and requires no sign-in.
Secured access enables sign-in and lets you configure the first administrator
during setup.

To install the platform into another writable directory:

```bash
kb-create install --platform-root /path/to/kb-platform
```

The install command downloads and verifies platform artifacts, installs
packages, writes configuration, starts the host, verifies the installation,
and configures the `kb` shim. Its success output gives the next command, for
example `cd ~/any-project && kb commit`.

The default install includes a built-in local adapter pack and does not ask you
to choose adapter providers. In a project, `kb adapter list --json` shows
`storage` as `@kb-labs/adapters-fs` with its effective `<KB_HOME>/state/<projectId>/storage` directory;
cache uses the platform-local StateBroker; and logging, analytics, and local
databases use Pino, a ring buffer, and SQLite. Event delivery, plugin invoke,
artifacts, config, and notifications use in-process implementations. No
external adapter service is needed for these defaults. All projects use the
platform defaults and platform-level overrides.

LLM and vector-store slots remain empty until you configure providers. A
command needing a missing capability reports a typed unavailable error with
the next `kb adapter bind <slot> ...` action. Embeddings also require a chosen
model provider; the installed filesystem snapshot provider is not used as the
runtime's optional `snapshotManager`.

## Check or diagnose an installation

```bash
kb-create status
kb-create doctor
```

Both commands accept `--platform-root PATH` when you installed outside the
default `~/kb-platform` directory. Doctor reports health checks and, when it
finds a repairable problem, gives a recovery command.

## Agent and CI installation

Use `apply --json` with the sealed release index and an explicit platform
root. This path is non-interactive and produces machine-readable output:

```bash
kb-create apply --json --index ./release-index.json \
  --platform-root ./ci-platform --service-profile default \
  --scenario commit
```

Use the release index for the release train being installed. The launcher
validates its digest and compatibility relations before it writes packages.
Do not use a hand-built index or copy version metadata from another release.

## Uninstall

```bash
kb-create uninstall --yes
```

In a terminal, uninstall lists the platform root, installed services, receipt,
and snapshots it will remove, confirms that project files are kept, and asks
before proceeding. Non-interactive callers must pass `--yes`; without it the
launcher returns an error with the exact command to rerun.

To remove an installation outside the default location, supply the same
`--platform-root PATH` used for install.

## Installation errors

These are the common errors reported by the installer, with recovery guidance
from the error catalog:

| Error code | Meaning | Recovery |
| --- | --- | --- |
| `KB_NODE_VERSION_UNSUPPORTED` | Node.js is on a major outside the supported policy. | Run the version-switch command shown in the diagnostic, then retry `kb-create install`. |
| `KB_INSTALL_MEMORY_INSUFFICIENT` | Available memory is below 1.20 GiB. | Close memory-heavy applications or increase machine memory, then run `kb-create install` again. |
| `KB_INSTALL_NO_DISK_SPACE` | There is not enough free disk space. | Free disk space or choose another writable directory with `kb-create install --platform-root PATH`. The preflight minimum is 2 GiB. |
| `KB_INSTALL_PACKAGE_MANAGER_KILLED` | The package manager was killed, likely because memory ran out. | Free memory, then rerun `kb-create install`. |
| `KB_INSTALL_PORT_IN_USE` | A required port is occupied. | Stop the process using the port named in the error, then rerun `kb-create install`. |

## Configure an LLM (optional)

`kb commit` can run without an LLM by using its heuristic path. To enable
OpenAI-backed generation, configure the adapter and keep the key in an
environment variable:

```bash
kb config set --scope platform platform.adapters.llm @kb-labs/adapters-openai
kb config set --scope platform platform.adapterOptions.llm.apiKey '${OPENAI_API_KEY}'
export OPENAI_API_KEY=your-openai-api-key
```

See [Configuration → kb.config](/configuration/kb-config) for configuration
scopes and adapter options.
