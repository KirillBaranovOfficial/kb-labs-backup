## Выберите режим доступа

Локальная установка принимает соединения только с этого компьютера и выполняет запросы от имени `local-admin`. Вход не требуется. Защищённый режим требует учётную запись для Studio и API Gateway. Выберите его, если доступ нужен коллегам или удалённым агентам.

## Вход и приглашения

Администратор входит по адресу Gateway и приглашает коллегу в Studio на странице **Admin → Invites**. Для обычной работы с проектами выберите роль `member`. Передайте ссылку `/activate/<token>` напрямую: Gateway не отправляет письма. Участники могут работать с проектами, плагинами и workflow, но не могут управлять пользователями, приглашениями и настройками платформы.

## Восстановление доступа

Администратор может скопировать одноразовую ссылку для сброса пароля на странице **Admin → Users** или создать её через CLI:

```bash
kb auth reset-link --user-id usr_123
```

Замените `usr_123` на ID пользователя. Ссылка действует один час, используется один раз и при активации отзывает все текущие сеансы пользователя. Передайте её пользователю напрямую.

Если ни один администратор не может войти, остановите host и восстановите администратора как локальный оператор:

```bash
kb-create stop
kb-create doctor --recover --email admin@example.com --tenant kb-cloud --password-stdin --yes
kb-create start
```

Введите новый пароль через стандартный ввод. Укажите tenant, настроенный для администратора. Флаг `--generate` поручает doctor создать новый пароль.

## API-доступ для агента

Создайте персональный токен для агента или CI:

```bash
kb auth tokens --name "nightly CI"
kb auth tokens
kb auth tokens --revoke tok_abc123
```

Токен наследует права владельца, действует 90 дней, а список и отзыв доступны только владельцу. Секрет показывается только при создании. Храните его в хранилище секретов CI и передавайте как Bearer-токен.
