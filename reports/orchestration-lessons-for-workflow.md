# Orchestration lessons for Workflow

| Incident | Workflow requirement | Stream |
|---|---|---|
| A run can own an unbounded number of resources, so copying all cleanup outcomes into one bounded teardown event can prevent the terminal lifecycle notification from being written. | Keep complete per-resource outcomes in the durable run record; emit a bounded teardown summary with outcome counts, full sampled failure identities, and an exact omission count. Consumers that correlate outcomes read the record. | x204-kb-runner-cutover-readiness |
| A run-token match can identify a supervising caller or keeper ancestor as a cleanup candidate if that descriptor is inherited or ownership history is too broad. | The single signal boundary protects the keeper's identity and current ancestor chain independently of ownership matches, and records each signal's PID, start identity, and ownership reason; the token is held only across the command's ExtraFiles boundary. | x204-kb-runner-cutover-readiness |
| A test-only cleanup helper directly signaled a recorded keeper PID without applying the proc caller/ancestor rail, killing the test process during helper replacement. | Test cleanup and deliberate keeper-loss actions use the same record-derived signal owner as production; the recorded keeper PID has a distinct Go type, and the owner refuses caller/ancestor identities with attribution. | x204-kb-runner-cutover-readiness |
| A latest-tag waiter had no appearance deadline when a launcher failed before writing its run record, so a typo or failed launch could block orchestration indefinitely. | A waiter bounds how long it waits for the first matching durable run record, reports typed not-found with a next step, and keeps the run-completion wait separate after the record appears. | x204-kb-runner-cutover-readiness |
| A process exited between Darwin's process-tree snapshot and governor metric read; a zero-length `kern.proc.pid` result became EIO and failed admission of an unrelated heavy run. | Treat a process that disappears during metric sampling as unavailable on every supported OS, while preserving real inspection errors and their errno. | x212 round 7 |
| An admitted outside test could write stdout/stderr until its timeout, filling runner disk and forcing whole-file reads into memory. | Every supervised test output stream has a hard byte ceiling, bounded retained head/tail, and process-tree cancellation when the ceiling is exceeded. | x212 round 8 |
| A devkit selector chose package dependents for tracked changes while task keys omitted package-owned files outside declared globs and transitive dependency content. | Cache validity mirrors selection from one ownership map: hash all tracked unowned files globally, every tracked file owned by the task package locally, and all tracked files in its transitive workspace dependency closure. Preserve generated dependency outputs, ignore untracked files, and hash current working-tree contents for modified tracked files. | x183 round 18 |
