## Status

## Head-of-line decision (round 1, task item 4)

**Keep head-of-line FIFO; no change.** S-237.26 and S-237.51 specify: "Admission is FIFO among runs competing for the same gate, slot group, or resource budget; an unrelated run may start around an earlier wait." A disk-blocked head therefore holds later runs in its slot group and holds later disk-sensitive runs across groups (`admissionResourcesOverlap`, `admission.go:355`), while unrelated runs pass. Reason to keep: launch-order guarantees within a slot group, and disk/quota accounting is order-dependent — letting later runs barge past a blocked head can starve it indefinitely. The defects were cost (fixed) and visibility (already specified by S-237.10/.16), not ordering.

## Visibility check (round 1, task item 3 — exists, nothing added)

While blocked on disk, the run already states condition + required vs free bytes on every existing surface: blocked event with `reason` "disk budget: need X plus min-free Y, have Z with R reserved" plus `disk_need_bytes`/`disk_free_bytes` (`admission.go:332-333`, event fields `proc.go:87-88`), record `WaitReason` shown by `kb-runner ps`, and the human feed's single `LOW DISK` line with need/free/remedy rendered by the workspace daemon from that event (S-237.16). The committed admission test pins the record-side wait reason. No second reporting path added.

# Round 2

## Status

DONE. `waitRun` no longer rescans finished history per tick (measured: **1.52 s → 0.008 s CPU per 3 s window** at 4000 finished records, same budget as admission), the crash window between the finished write and the live removal is closed (the finished record is the truth), and a record without a status is now a typed decode error naming the file. Every per-tick path in `clikit/proc` reads O(live)+O(1) records; the full registry is consulted only at wait start and on an enqueue-watermark change. Four mutations verified red, then reverted. Three consecutive all-green runs of the seven claiming tests.

## Root causes found (round 2 items)

1. **`waitRun` same defect** (`tools/clikit/proc/admission.go:971`): read the all-records set every 250 ms tick. Fixed with the construction below.
2. **Crash window** (`admission.go`, `writeRecordAtomic:565` + `pruneStateLocked:654`): between the finished rename and the live removal, a crash left a live file with the stale non-terminal status; the next prune ran `markLostLocked` through it and **overwrote the real exit code with `lost`** (proved: committed test failed pre-fix with "prune overwrote the finished record instead of treating it as the truth").
3. **`rec.Status == ""` retirement**: writer audit shows **no producer exists** — every explicit writer sets one of the seven valid statuses (`reserveAdmission`: queued/starting/blocked; keeper: running; `markLostLocked`/`markRunDirty*`: lost/dirty; `completeRecord`: dead; `GarbageCollect`: dead/dirty; the ready path backfills its in-memory "" to starting before writing), and the remaining writers only preserve an already-written status. The live registry on this machine (1401 record files — the earlier 2776 figure included companion directories) has **zero** records without a status. Empty/unknown status is therefore corruption → typed decode error (`admission.go:712`), consistent with the existing "decode run record" error.

## Design deltas (round 2)

- **`waitRun`** (`admission.go:971`): one full-registry consult at start (also resolves a tag that finished before the wait began); afterwards each tick reads the **live set** (`readLiveRecordsLocked`), the **matched run's record by ID** (`readRecordLocked` — covers the retirement transition), and the **enqueue watermark** (`readQueueSequenceLocked:456`, O(1) file read). A watermark change means a run was enqueued after the last consult — it may already have finished and retired between two polls — so that tick does exactly one full-registry consult. This closes the appear-and-finish-between-polls hang window that a live-scan-only shape would have introduced (a supervised `/bin/true` run's whole lifecycle fits inside one 250 ms poll). The watermark consumes the existing enqueue-order owner (`queue-sequence`, written once per run under the state lock by `nextQueueOrderLocked:479`); it is not a second declaration. `readQueueSequenceLocked` is extracted from `nextQueueOrderLocked`, which now uses it — one decoder.
- **Prune** (`admission.go:654`): per live file, in order — (a) if a finished record with the same RunID exists, the live file is a stale leftover and is **removed without any status transition** (the finished record keeps its recorded exit; covers crash windows); (b) else a terminal status is retired by byte-preserving rename (invariant enforcement); (c) known live statuses keep today's keeper-identity logic; (d) anything else is `decode run record <path>: unknown run status "<s>"`.
- **Unlocked writers eliminated** (`resources.go`): `markRunDirtyWithoutLock`/`markRunLostWithoutLock` were the only record writers that wrote **without the state lock** (best-effort path when lock entry failed, `resources.go:549`). They raced the new twin-check rename (a stale-live rename could overwrite their fresh finished write). `markRunDirtyWithoutLock` was also a duplicate of `markRunDirty`; both are replaced — call sites now use the lock-acquiring `markRunDirty`/new `markRunLost` (`resources.go:661`). Every record write in the package is now state-lock-held, so the twin check and retirement are race-free.
